# 补齐 SSH ChaCha20

## 目标

Electron 缺少原生 `chacha20` 时，Netcatty 仍能安全连接仅接受 `chacha20-poly1305@openssh.com` 的 SSH 服务。沿用现有 ssh2、认证、主机校验和连接接口。

用户已审阅 FEATURE-942 的评估附件，确认建议范围，并在评论「那就补齐吧」授权实施。无需重复请求批准。

## 要求

- 锁定生产依赖 `@noble/ciphers@2.2.0`，仅使用原始 `chacha20orig` 补齐流加密。
- 在既有 ssh2 补丁中接入，复用其 Poly1305、包处理和恒定时间标签校验，保留全部已有补丁。
- 同步 ssh2 支持列表和应用共享过滤；默认、legacy、自定义列表与实际后端一致，AES 顺序和运行限制不变。
- 保留主机密钥校验、每跳认证与错误处理，不记录私钥、密码或完整主机资料。
- 覆盖终端、命令、SFTP、跳板、转发共用路径；构建独立 macOS arm64 测试包。
- 发布包能力检查覆盖加密、密钥交换和签名；构建后失败应阻止上传，防止 Electron 升级再次引入能力缺口。

| --- | --- | --- |
| AC-1 | 无原生 ChaCha20/addon 时，SSH 与 SFTP 列表包含可运行的 SSH ChaCha20；缺后备时不误报支持 | 算法单测、子进程失败夹具 |
| AC-2 | 原始流加密与 OpenSSL 参考一致，SSH 包可互通，篡改不交付明文 | 向量、分片/大包/序号/错误长度/标签测试 |

| AC-4 | 信任匹配成功、换密钥拒绝，双方向 AES/ChaCha20 跳板与转发沿用现有路径 | 隔离集成测试、既有主机校验测试 |
| AC-5 | 构建包内依赖、WASM 和动态 import 正常；路由器只读连接验证 | macOS arm64 包及路由器 smoke，明确其他平台未实机验证 |
| AC-6 | lint、项目测试、构建通过，交付自有 fork main 的 PR | 命令记录及 PR |
| AC-7 | 发布包内6种现代 cipher、Curve25519/ECDH、Ed25519/RSA-SHA2/ECDSA可执行，且不能借用开发目录依赖 | 当前架构包内 Electron 自检，构建上传前执行 |

## 不做

不加入抗量子 KEX、旧 CAST128、新 UI 开关或系统 SSH 后端，不修改路由器、不覆盖日常安装进行初测。
